# Local code and UX pass, November 21, 2026

No Git remote is configured in this app checkout. Nothing was pulled, rebased,
discarded, committed or published. The pass used the latest local working tree
at `Ryan's Folder/Projects/Loopstack`, preserving the substantial uncommitted
desktop work. This is a tested cleanup pass, not a clinical validation or an
exhaustive security certification.

## Fixed and tested

- Startup catches a rejected Nightscout configuration read. An unavailable
  sessionStorage write no longer prevents the React app from mounting.
- Nightscout reads have a request generation. A later sample selection or read
  wins over an older in-flight response. Empty/invalid CGM responses cannot
  become a real-data dashboard. Startup rechecks the sample preference after
  reading the connector configuration.
- Meal comparisons stop at the reporting cutoff and before the next substantial
  meal. The next meal's two-hour reading and boundary glucose no longer appear
  in the earlier meal. Duplicate timestamps/invalid records cannot inflate the
  minimum sample count. This retains the existing attribution rule rather than
  introducing a new combined-meal model.
- Meal windows use binary bounds on sorted readings and a reverse next-meal
  lookup instead of rescanning the full glucose history for each meal. No field
  performance or clinical improvement is claimed.
- Non-finite, zero and negative measured settings values fail the existing
  suggestion gate. This does not generate or apply new therapy values.
- Malformed care contacts, notes and tracked confidence histories recover
  without crashing; valid records and choices remain available.
- Browser history updates the route reference alongside rendered route state.
- The AI screen is locked while its connection is checked. Rejected connection
  checks and message requests become recoverable UI states, not stuck spinners.
  Ask preserves a newer draft typed while a previous request is pending.
- Dashboard drag/resize state recovers on lost capture and window blur. A second
  pointer cannot replace an active drag/resize. Menu Home/End, arrow-open and
  account-menu Tab behavior follow the existing keyboard interaction pattern.
- The selected-hour readout moves with transform rather than left, using the
  existing fast timing/ease tokens. The food-detail notch no longer animates
  left. Existing reduced-motion handling remains. No decorative loops added.

## Dashboard proposal, not installed UI

`docs/desktop/dashboard-focus-preview.html` is a local, interactive direction
study with clearly labelled illustrative data. It preserves LoopStack's
semantic tokens and calm health-data mode. Variance 4, motion 1, density 7,
system rigor 9. It does not replace the customizable dashboard or fixed report.
It uses absolute local stylesheet links and is not a portable deployment.

Borrow the information pattern, not another product's identity:

- [Oura's app structure](https://support.ouraring.com/hc/en-us/articles/360058599753-How-to-Use-the-Oura-App)
  separates today's state, vitals and longer-term health. The proposed LoopStack
  view leads with current glucose and one relevant historical observation.
- [Withings Smart Trends](https://support.withings.com/hc/en-us/articles/52926154847889-Withings-App-Smart-Trends-Withings-Only)
  connects an observed trend to a contextual conversation. LoopStack should
  preview the chosen hour/day evidence before sending any question. No automated
  treatment advice is borrowed.

Next proposal: current state, a weekday/hour evidence explorer, then a queue
that distinguishes observations, drafts, committed changes and installed builds.
The preview's weekday rows are illustrative, not a new live chart implementation.
The context-question button reveals a draft and sends nothing.

## Follow-up, later the same day

- **Weekday/hour explorer:** already built from the proposal (the
  `hour-evidence` and `review-queue` tiles, a saved-layout migration, and Ask
  opening with the hour summary visible before anything is sent). Checked in the
  browser: dashboard → dates behind an hour → Ask.
- **Tracking by source:** tracked suggestions and the badge's seen list are now
  kept per data source: `loopstack.tracked.sample` and one store per Nightscout
  site, keyed by a hash of the site (no address in the key). This was a live
  bug, not only a multi-account concern. Suggestion ids (`isf`, `carbRatio`,
  `basal-07`) are the same for every patient, so staging one on the sample
  patient staged the person's own reading for their next build. **Migration
  policy:** the first Nightscout site to load takes over the old shared store,
  and the old key is removed. The sample patient starts empty. A read whose
  site address is unavailable doesn't take it over.
- **Bundle:** every view except the dashboard is lazy-loaded, and `Diff` moved
  to `ui/Diff.tsx` so a dashboard tile doesn't pull in the Feature library. The
  first chunk went from 516 kB to 396 kB (gzip 160 → 129 kB), and Vite's size
  warning is gone. All seven views loaded in headless Electron from
  `desktop/dist` over `file://` with the page CSP, with no console errors.

  cancellation, and binding drafts to the repository/branch that produced them.
